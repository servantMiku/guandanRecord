# 掼蛋小程序 - 赛季总场次与荣誉门槛功能开发计划

## 概述

为掼蛋比赛成绩记录小程序增加两个核心功能：
1. **赛季总场次管理**：支持设置赛季总场次，到达总场次或超过结束日期时自动结束赛季并清空历史数据
2. **荣誉统计门槛**：设置参赛场次比例门槛（默认80%），只有达到门槛的玩家才参与荣誉统计，同时在统计页面显示赛季剩余场次

平台：mobile（微信小程序）

## 技术方案

| 维度 | 选择 | 理由 |
|------|------|------|
| 数据存储 | Supabase (现有) | 延续现有架构，无需迁移 |
| 配置存储 | 前端 localStorage | 荣誉门槛比例是用户级配置，无需后端存储 |
| 赛季自动结束 | 后端 + 前端双重检查 | 创建战绩时后端检查，前端展示时也检查 |
| 数据清空 | 软删除 (is_deleted=true) | 保留数据但标记删除，避免误操作导致数据丢失 |

## 功能模块

### 1. 赛季总场次管理

**后端改动：**
- `seasons` 表增加 `total_matches` (int, 默认null) 和 `current_matches` (int, 默认0) 字段
- 创建/编辑赛季时支持设置总场次
- 创建战绩时自动检查：如果 `current_matches >= total_matches`，自动结束赛季
- 赛季结束接口增加清空数据逻辑：将 `matches` 和 `player_stats` 中该赛季的数据标记为 `is_deleted=true`
- 查询战绩和统计时排除已删除数据

**前端改动：**
- 赛季管理表单增加"总场次"输入框
- 赛季卡片显示进度："当前X场 / 总Y场"
- 结束赛季时确认提示增加"将清空历史数据"警告

### 2. 荣誉统计门槛

**配置存储：**
- localStorage key: `guandan_award_threshold`，默认 80
- "我的"页面增加滑块/输入框配置门槛比例（50%-100%）

**后端改动：**
- 统计接口增加 `threshold` 参数（可选，默认80）
- 计算奖项前过滤：只有 `total_matches >= season_current_matches * threshold / 100` 的玩家参与奖项评选
- 返回数据中增加 `totalMatchesPlayed`（赛季总场次）和 `remainingMatches`（剩余场次）

**前端改动：**
- "我的"页面新增"荣誉门槛配置"区块
- 统计页面顶部显示赛季进度："第 X 场 / 共 Y 场（剩余 Z 场）"
- 荣誉墙只展示达到门槛的玩家
- 未达到门槛的玩家在统计列表中灰色显示或标注"未达门槛"

### 3. 数据结构变更

```typescript
// seasons 表新增字段
totalMatches?: number     // 赛季总场次（可选）
currentMatches: number   // 当前已进行场次（默认0）

// stats 接口返回新增字段
totalMatchesPlayed: number   // 赛季总场次
remainingMatches: number     // 剩余场次
threshold: number            // 当前使用的门槛比例
```

## 实施步骤

1. **阶段一：原型设计** — 加载 `design-canvas` 技能，完成赛季管理表单、统计页面进度条、我的页面门槛配置的 HTML 原型设计。原型完成后提示用户确认，确认后进入开发阶段。

2. **数据库 schema 变更与后端基础改造** — 修改 `schema.ts` 增加 `total_matches` 和 `current_matches` 字段；更新 seasons controller 支持新字段的 CRUD；修改 matches controller 创建战绩时自动增加 `current_matches` 并检查是否达到总场次。

3. **后端赛季自动结束与数据清空** — 实现赛季自动结束逻辑（到达总场次时）；实现赛季结束时的数据清空（软删除 matches 和 player_stats）；更新查询逻辑排除已删除数据。

4. **后端统计接口门槛过滤** — 修改 stats controller，支持 `threshold` 参数；计算奖项前过滤未达门槛玩家；返回数据中增加 `totalMatchesPlayed`、`remainingMatches`、`threshold`。

5. **前端赛季管理页面改造** — 在 `seasons/index.tsx` 表单中增加"总场次"输入；赛季卡片显示进度信息；结束赛季提示增加清空数据警告。

6. **前端"我的"页面配置门槛** — 在 `profile/index.tsx` 增加"荣誉门槛配置"区块；使用 Slider 或 Input 设置比例（50%-100%）；存储到 localStorage；新增玩家时同步检查是否影响统计。

7. **前端统计页面展示优化** — 在 `stats/index.tsx` 顶部显示赛季进度条（当前场次/总场次/剩余场次）；荣誉墙只展示达到门槛的玩家；未达门槛玩家列表中标注状态。

8. **联调测试与边界处理** — 测试赛季自动结束流程；测试荣誉门槛过滤逻辑；处理无总场次赛季（兼容老数据）的边界情况。

## 页面规格

##### @nav(mobile-tabbar)
> type: tabbar
> platform: mobile

- @page(/) 战绩 | icon: home
- @page(/stats) 统计 | icon: bar-chart
- @page(/arrange) 对阵 | icon: users
- @page(/profile) 我的 | icon: user

##### @page(/seasons) 赛季管理

**核心职责**：管理赛季生命周期，支持设置总场次和自动结束。
**访问路径**：从 @page(/profile) 我的页面进入。
**布局**：
- 顶部：页面标题 + 新建按钮
- 表单弹窗（新建/编辑）：名称、开始日期、结束日期、总场次
- 列表区：活跃赛季卡片、已结束赛季卡片

**交互说明**

| 元素 | 动作 | 响应 | 传参 | 备注 |
|------|------|------|------|------|
| 新建按钮 | 点击 | 显示表单弹窗 | — | — |
| 总场次输入框 | 输入 | 实时校验数字 | — | 可选，为空表示不限制 |
| 保存按钮 | 点击 | 提交创建/编辑 | — | 校验总场次>=0 |
| 结束按钮 | 点击 | 弹出 @modal(confirm-end) | seasonId | — |
| 赛季卡片 | 查看 | 显示进度信息 | — | 活跃赛季显示"X/Y场" |

**弹窗 confirm-end**：
- 标题："确认结束赛季"
- 内容："结束赛季后将清空该赛季的所有历史数据，此操作不可恢复。确定要结束吗？"
- 操作：确认（结束并清空）、取消（关闭弹窗）

##### @page(/profile) 我的

**核心职责**：管理玩家和系统配置。
**访问路径**：Tabbar 直达。
**布局**：
- 顶部：页面标题
- 玩家管理区块：玩家列表 + 新增玩家
- 赛季管理入口：跳转 @page(/seasons)
- 荣誉门槛配置区块（新增）：滑块 + 当前比例显示
- 数据管理区块：导入/导出/清空

**交互说明**

| 元素 | 动作 | 响应 | 传参 | 备注 |
|------|------|------|------|------|
| 门槛滑块 | 滑动 | 实时更新比例显示 | — | 范围50-100 |
| 门槛输入框 | 输入 | 校验并更新比例 | — | 范围50-100 |
| 新增玩家按钮 | 点击 | 展开输入框 | — | 已有功能 |

##### @page(/stats) 统计

**核心职责**：展示赛季统计数据和荣誉墙。
**访问路径**：Tabbar 直达。
**布局**：
- 顶部：赛季选择器 + GOAT切换
- 赛季进度条（新增）：当前场次/总场次/剩余场次
- 赛季总结
- 荣誉墙：只展示达到门槛的玩家
- 排名表格：全部玩家，未达门槛的灰色标注

**交互说明**

| 元素 | 动作 | 响应 | 传参 | 备注 |
|------|------|------|------|------|
| 赛季选择器 | 切换 | 刷新统计数据 | seasonId | — |
| GOAT切换 | 切换 | 切换统计模式 | isAllTime | 全量统计不显示门槛 |
| 问号按钮 | 点击 | 展开/收起奖项规则 | awardId | 已有功能 |

**列表项字段**：排名 / 玩家 / 场次 / 胜场 / 胜率 / 状态（达标/未达标）
